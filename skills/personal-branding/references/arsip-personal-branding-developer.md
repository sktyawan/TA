# Arsip: Modul Personal Branding Developer (Seti)

> **Status: ARSIP.** Modul di bawah ini adalah versi lama skill ini (fokus ke Seti sebagai developer di GitHub/LinkedIn/X). Sejak upgrade 2026-10-08, skill `personal-branding` fokus ke **persona Sasa Berlian** (lihat SKILL.md). Modul ini disimpan agar tidak hilang — hanya dipakai bila Seti secara eksplisit meminta optimasi profil developer-nya.

## Positioning statement developer

Format: `[Role] yang membantu [audiens] [hasil konkret] lewat [cara/stack khas]`. Maksimal 15 kata, lolos uji 5 detik oleh orang asing. Contoh benar: "Full-stack developer yang membantu UMKM otomatisasi operasional lewat AI agents & integrasi API." Contoh salah: "Passionate developer yang suka coding dan belajar hal baru." Varian padat: `[Role] | [niche] | [bukti]`. Bahasa: default Indonesia; versi Inggris 1 baris bila target internasional (maknanya setia, bukan positioning berbeda).

## README profil GitHub

Struktur baku: (1) sapaan + positioning 2–3 baris; (2) badge stack maksimal 10, hanya teknologi yang terbukti dipakai di repo publik; (3) proyek unggulan 3–6 repo, 1 kalimat hasil per repo; (4) statistik (opsional, hanya bila kontribusi 3 bulan terakhir tidak kosong); (5) sedang dikerjakan 1–2 baris konkret; (6) kontak yang aktif saja. Aturan: tanpa emoji berlebihan (maks 1 per baris section), tanpa GIF, tanpa kalimat klise, satu bahasa per section. Pola badge: `https://img.shields.io/badge/<Nama>-<HexWarna>?logo=<logo>&logoColor=white`.

**Aturan data (wajib):** jangan mengarang nama repo, angka, atau link. Data yang belum diketahui ditulis `[TBD]` dan ditanyakan ke Seti — jangan biarkan placeholder lolos ke output final.

## Pinned repositories

GitHub hanya memberi 6 slot — perlakukan sebagai etalase. Skor 1–5 tiap kriteria: relevansi positioning, kualitas README repo, keaktifan (commit 6 bulan terakhir), bukti skill yang dicari pasar. Pilih 6 skor tertinggi; seri dimenangkan yang paling relevan dengan positioning lalu commit terbaru. Repo skor rendah tapi penting: poles dulu (README minimal: apa ini, cara jalan, 1 screenshot) baru pin. Jangan pin repo kosong/tanpa README, dan jangan pin fork kecuali Seti kontributor aktif. Review ulang tiap 3 bulan atau tiap ada proyek baru selesai.

## Konsistensi identitas lintas platform (developer)

Yang harus selaras GitHub ↔ LinkedIn ↔ X: nama tampilan, foto profil, positioning 1 kalimat (README/headline/bio), link silang, pola username/handle. Ketidakselarasan dilaporkan sebagai daftar perbaikan konkret ("ganti X menjadi Y di platform Z").

## Kalender konten LinkedIn (arsip)

Pilar: build in public 40%, insight teknis 30%, opini 20%, personal/milestone 10% (maks 1 per 2 minggu). Frekuensi 3–5 posting/minggu. Format: teks pendek 150–300 kata (hook di 2 baris pertama), carousel 5–10 slide (1 ide per slide, maks 25 kata), polling maks 1 per 2 minggu. Jam posting WIB: Selasa–Kamis 07:30–09:00 / 12:00–13:00 / 19:00–21:00; hindari Senin pagi dan Jumat sore. Setiap posting: 1 hook + 1 isi bernilai + 1 CTA pertanyaan. Balas setiap komentar dalam 24 jam pertama.

## Strategi pertumbuhan X (arsip)

Bio = positioning + 1 bukti + 1 CTA/link, maks 160 karakter. Pinned tweet: tweet terbaik, ganti tiap ada pencapaian lebih besar. Reply strategy: 10–20 akun target (niche, 1K–100K followers), 5–10 reply berkualitas/hari yang bisa berdiri sendiri sebagai tweet — bukan "setuju"/"keren bang". Struktur thread: tweet 1 hook, tweet 2–6 isi (1 poin per tweet), tweet terakhir ringkasan + CTA; 5–8 tweet, maks 240 karakter per tweet. Loop mingguan: 1 thread + 3–5 tweet pendek, reply 5–10/hari, quote tweet 1–2/minggu; ukur impressions/profile visits/follower baru tiap minggu.
