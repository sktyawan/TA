## 1. Apa yang dilakukan skill ini

Skill ini memberi Dinda kapabilitas operasional penuh untuk menjalankan strategi freelance Seti di Upwork:

- **Optimasi profil Upwork**: menyusun title, overview (terutama hook 2 baris pertama), memilih skill tags, menyusun item portfolio, dan menetapkan rate awal vs rate target.
- **Proposal & cold outreach**: menulis proposal Upwork dan email cold outreach dengan struktur yang terbukti (hook personalisasi → bukti relevan → CTA), plus template reusable dengan slot personalisasi yang jelas.
- **Pricing strategy**: menghitung rate dari biaya hidup + margin + fee platform, memilih antara fixed-price vs hourly, dan menentukan kapan saatnya menaikkan rate.
- **Side gig discovery**: menemukan peluang gig di luar Upwork (komunitas, job board, direct outreach) dan menilai kelayakannya dengan kriteria scoring.

Skill ini TIDAK mengerjakan pekerjaan klien itu sendiri (itu domain agent lain); fokusnya pada akuisisi pekerjaan, positioning, dan monetisasi.

## 2. Kapan dipakai

Dinda memuat dan memakai skill ini ketika menerima permintaan seperti:

- "Buatkan / perbaiki profil Upwork saya"
- "Tuliskan proposal untuk job posting ini"
- "Berapa rate yang pas untuk saya?"
- "Carikan gig / job board / peluang freelance di luar Upwork"
- "Review proposal saya sebelum dikirim"
- "Kapan saya bisa naikkan rate?"
- "Buatkan template cold email untuk calon klien"
- "Analisis kenapa proposal saya tidak direspons"

Jika permintaan hanya sebagian (misalnya hanya pricing), kerjakan hanya bagian itu — jangan memaksakan seluruh playbook.

## 3. Playbook / prosedur inti

### A. Optimasi profil Upwork

Kerjakan dalam urutan ini. Setiap elemen punya format target yang harus dipenuhi.

**A1. Title (maks 70 karakter)**
- Format: `[Spesialisasi inti] | [Hasil yang dijual]`. Contoh: `Full-Stack Developer | Web App & Dashboard HR`.
- Jangan pakai gelar generik ("Programmer", "Freelancer"). Pakai niche + outcome.
- Jika Seti punya lebih dari satu niche, buat satu specialized profile per niche, bukan satu title campur aduk.

**A2. Overview — hook 2 baris pertama adalah segalanya**
- Hanya 2 baris pertama yang terlihat sebelum klien klik "more". Tulis dulu 2 baris ini sebagai headline:
  - Baris 1: klaim hasil spesifik. Contoh: "Saya membangun dashboard HR yang dipakai 200+ karyawan — dalam 3 minggu."
  - Baris 2: diferensiasi. Contoh: "Spesialis: web app data-heavy, integrasi API, dan otomasi."
- Struktur overview penuh:
  1. Hook 2 baris (hasil + diferensiasi).
  2. 3–5 bullet pencapaian terukur (angka wajib: waktu, skala, hasil).
  3. Daftar layanan konkret (bukan "saya bisa apa saja").
  4. CTA singkat: "Kirim pesan dengan detail proyek Anda — saya balas dengan estimasi dalam 24 jam."

**A3. Skill tags**
- Pilih 10–15 tag. Prioritas: tag yang muncul di job posting target (salin bahasa klien, bukan bahasa CV).
- Hapus tag generik ("Microsoft Word") kecuali relevan dengan niche.

**A4. Portfolio item**
- Setiap item wajib punya: judul hasil (bukan judul proyek), 1 screenshot/gambar, 3 baris deskripsi (masalah → aksi → hasil terukur), dan skill yang dipakai.
- Minimal 3 item sebelum profil dianggap "siap tempur". Jika belum ada proyek klien, pakai proyek pribadi / open source dengan hasil yang terukur.

**A5. Rate awal vs rate target**
- Rate awal = rate untuk 3–5 job pertama (tujuan: review 5 bintang, bukan profit maksimal). Hitung dengan rumus di bagian C, lalu boleh turunkan 10–20% khusus untuk job pertama.
- Rate target = rate setelah 5+ review bagus atau JSS ≥ 90%. Naikkan bertahap 15–25% per kenaikan, bukan lompat 2x.
- Cantumkan rate awal di profil; simpan rate target sebagai catatan internal dan review tiap 3 bulan.

**Output format bagian A:** berikan profil dalam blok terstruktur (Title / Overview / Skill tags / Portfolio item 1..n / Rate awal / Rate target) siap copy-paste, plus 2–3 kalimat alasan tiap pilihan penting.

### B. Proposal Upwork & cold email

**B1. Struktur proposal (150–250 kata, jangan lebih)**
1. **Hook personalisasi (2 kalimat pertama):** rujuk sesuatu yang SPESIFIK dari job posting — nama proyek, masalah yang disebut, atau detail teknis. Contoh: "Saya lihat Anda butuh migrasi data lembur dari spreadsheet ke database — saya baru menyelesaikan hal persis ini untuk modul payroll."
2. **Bukti relevan (1 paragraf):** satu contoh kerja paling mirip + hasil terukur. Jangan daftar semua pengalaman.
3. **Rencana singkat (2–3 bullet):** langkah konkret yang akan dilakukan di minggu pertama. Ini yang membedakan dari proposal generik.
4. **CTA:** satu kalimat ajakan diskusi + ketersediaan. Contoh: "Bisa mulai minggu ini — mau saya kirim estimasi detail setelah 15 menit call?"

**B2. Template reusable dengan slot personalisasi**
Simpan template dalam format ini; slot ditandai `[SLOT]` dan WAJIB diisi sebelum kirim:

```
Halo [NAMA_KLIEN],

Saya tertarik dengan [DETAIL_SPESIFIK_DARI_POSTING]. [KALIMAT_HUBUNGAN_DENGAN_PENGALAMAN].

Baru-baru ini saya [CONTOH_KERJA_MIRIP] yang menghasilkan [HASIL_TERUKUR].

Untuk proyek Anda, saya akan:
- [LANGKAH_1_MINGGU_PERTAMA]
- [LANGKAH_2_MINGGU_PERTAMA]

[PERTANYAAN_KLARIFIKASI_SATU_KALIMAT]?

Saya bisa mulai [KETERSEDIAAN]. Terima kasih,
Seti
```

**B3. Kriteria keputusan sebelum mengirim proposal**
- Kirim HANYA jika: (a) skill match ≥ 70%, (b) klien punya payment verified ATAU minimal 3 review bagus, (c) budget masuk akal untuk scope (cek dengan rumus bagian C), (d) job posting berumur < 7 hari (lebih tua = proposal tenggelam).
- Jika salah satu gagal: lewati, JANGAN kirim proposal "coba-coba".
- Maksimal 10 proposal aktif per minggu untuk menjaga kualitas personalisasi.

**B4. Cold email (di luar Upwork)**
- Subjek: spesifik, bukan "Jasa Freelance". Contoh: "Ide perbaikan dashboard HR [NamaPerusahaan]".
- Isi: 3 paragraf pendek — observasi spesifik tentang bisnis mereka, satu bukti hasil, satu CTA ringan (bukan "kapan meeting?", tapi "boleh saya kirim 1 contoh mockup gratis?").
- Follow-up 1x setelah 5–7 hari. Tidak ada respons setelah itu = berhenti, jangan spam.

**Output format bagian B:** proposal/email jadi dalam blok kode siap kirim + checklist 4 kriteria keputusan (lolos/gagal per item).

### C. Pricing strategy

**C1. Rumus rate per jam**
1. Hitung kebutuhan bulanan: biaya hidup + tabungan target + pajak/dana darurat.
2. Bagi dengan jam kerja realistis per bulan (bukan 160 — pakai 80–100 jam billable, sisanya untuk cari klien & admin).
3. Tambahkan fee platform Upwork (10% untuk kontrak baru; pakai 10% agar aman).
- Rumus: `rate = (kebutuhan_bulanan / jam_billable) × 1.15 (margin) × 1.10 (fee platform)`.
- Contoh: kebutuhan Rp10 juta / 90 jam = Rp111 ribu → ×1.15 = Rp128 ribu → ×1.10 = Rp141 ribu ≈ **Rp140 ribu/jam atau $9/jam**.

**C2. Fixed-price vs hourly — kapan pakai apa**
- **Hourly** jika: scope belum jelas, klien minta iterasi banyak, atau proyek maintenance/ongoing.
- **Fixed-price** jika: scope jelas dan Dinda/Seti sudah pernah mengerjakan hal serupa (estimasi akurat). Tetapkan milestone per 25–50% pekerjaan, JANGAN 100% di akhir.
- Aturan: fixed-price quote = estimasi jam × rate × 1.3 (buffer revisi). Jika klien minta revisi di luar scope, itu change order berbayar, bukan gratis.

**C3. Kapan menaikkan rate (cek tiap 3 bulan)**
Naikkan jika MINIMAL 2 dari 3 kondisi terpenuhi:
- Win rate proposal > 30% dalam 3 bulan terakhir (terlalu murah = terlalu mudah menang).
- JSS ≥ 90% atau 5+ review 5 bintang berturut-turut.
- Pipeline penuh: menolak/menunda klien karena kapasitas.
- Besaran kenaikan: 15–25%. Komunikasikan ke klien lama dengan notice 30 hari; klien baru langsung pakai rate baru.

**Output format bagian C:** tabel perhitungan (kebutuhan, jam, margin, fee, rate final dalam Rp dan $) + rekomendasi fixed vs hourly + status cek kenaikan rate.

### D. Side gig discovery

**D1. Sumber gig di luar Upwork (prioritas berurutan)**
1. **Direct outreach** ke bisnis lokal / kenalan: conversion tertinggi, tanpa fee platform.
2. **Komunitas**: grup Telegram/Discord/Facebook niche (developer Indonesia, startup, UMKM digital). Cari thread "butuh freelancer".
3. **Job board**: We Work Remotely, RemoteOK, Wellfound (startup), plus board lokal seperti Glints/Kalibrr untuk kontrak remote.
4. **Marketplace lain**: Fiverr (paket produk jelas), Toptal/Contra (kurasi ketat, rate tinggi).

**D2. Kriteria scoring gig layak (skor 1–5 per item, ambil yang total ≥ 18/25)**
- Budget masuk akal untuk scope (bandingkan dengan rumus bagian C).
- Klien komunikatif & jelas (respons cepat, brief tertulis).
- Scope terdefinisi (ada deliverable konkret, bukan "bantu-bantu").
- Potensi repeat/long-term (lebih berharga dari one-off).
- Reputasi klien bisa diverifikasi (website, review, atau referensi).

**D3. Prosedur mingguan**
- Senin: scan 3 sumber teratas, catat 5 prospek terbaik dengan skor.
- Kirim outreach/proposal ke 5 prospek itu paling lambat Rabu (pakai template B2/B4).
- Jumat: review respons, update skor, follow-up yang belum balas.

**Output format bagian D:** daftar prospek dalam tabel (sumber, deskripsi gig, skor per kriteria, total, aksi: kirim/tunda/lewati).

## 4. Contoh singkat

**Input:** Seti: "Tuliskan proposal untuk job posting ini: 'Need developer to build employee attendance dashboard, React + Supabase, budget $500, payment verified, posted 2 days ago.'"

**Proses (yang Dinda lakukan):**
1. Cek 4 kriteria B3: skill match tinggi (React+Supabase = stack Seti) ✓, payment verified ✓, budget $500 untuk dashboard standar = masuk akal ✓, posting 2 hari ✓ → LAYAK, kirim.
2. Isi slot template B2: detail spesifik = "attendance dashboard React + Supabase"; bukti = modul absensi yang pernah dibangun; rencana minggu pertama = 2 bullet konkret; CTA + ketersediaan.

**Output:**
```
Halo,

Saya tertarik dengan proyek attendance dashboard React + Supabase Anda. Saya baru membangun modul absensi dan dashboard HR dengan stack yang sama — dipakai untuk 200+ data karyawan dengan rekap otomatis.

Untuk proyek Anda, saya akan:
- Setup skema Supabase (tabel kehadiran, relasi karyawan) + auth di minggu pertama
- Bangun dashboard rekap harian/mingguan dengan filter departemen

Apakah data kehadiran saat ini masih di spreadsheet yang perlu dimigrasi?

Saya bisa mulai minggu ini — $500 fixed-price dengan 2 milestone. Terima kasih,
Seti
```
Checklist keputusan: 4/4 lolos. Rekomendasi: kirim hari ini.

## 5. Anti-pattern

- **Jangan** mengirim proposal massal tanpa personalisasi — 5 proposal personal > 50 proposal template mentah.
- **Jangan** menetapkan rate dari "rate pasaran" tanpa menghitung rumus C1 — pasaran tidak tahu biaya hidup Seti.
- **Jangan** mengambil job dengan scope kabur dan harga fixed — itu jebakan revisi tanpa akhir.
- **Jangan** menurunkan rate saat sepi order tanpa analisis dulu — cek dulu kualitas proposal dan targeting, bukan langsung banting harga.
- **Jangan** mengarang pengalaman, angka portofolio, atau review palsu — satu ketahuan = akun dan reputasi selesai.
- **Jangan** bekerja di luar kontrak Upwork yang tercatat (minta bayaran via transfer langsung untuk job dari Upwork) — melanggar ToS dan menghilangkan proteksi payment.
- **Jangan** menjanjikan deadline yang tidak bisa dipenuhi demi memenangkan bid — keterlambatan merusak JSS lebih parah daripada kalah bidding.
- **Jangan** follow-up cold email lebih dari 1x — spam menghancurkan reputasi outreach.
- **Jangan** mencampur niche dalam satu profil — satu profil satu positioning yang tajam.
- **Jangan** memberikan kerja gratis "sebagai tes" melebihi 1–2 jam — tes berbayar atau tidak sama sekali.
